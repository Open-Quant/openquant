## Why

The package has no way to get market data. Notebook 06 scrapes Stooq inline, and nobody has checked Stooq's
terms (brief hypothesis H2). No run records which data it used. RQ-011 asks for a documented data layer that
fetches, caches and hashes daily OHLCV from a source whose terms are recorded. Issue #43 has the owner's
decision from 2026-09-19: a pluggable, fetch-only adapter where the user supplies the source and key, plus a
small redistributable sample for CI and the docs. The sample is chosen only after candidate sources have been
researched and brought to the owner.

## What Changes

- Add `openquant.data.fetch(symbols, start, end, *, source, cache_dir, refresh, offline, return_meta)`.
- Add the `DataSource` protocol and three sources: `LocalSampleSource` (the committed sample),
  `LocalFileSource` (a user's own file) and `CallableSource` (a user's own fetch function). No
  vendor-specific network adapter.
- Cache each (source, symbol, range) request on disk as Parquet with a JSON sidecar (format
  `openquant-ohlcv-cache-v1`).
- Add `dataset_hash`, a deterministic content hash (`oq-dataset-sha256-v1`), and `record_dataset_hash`.
  `experiments/run_pipeline.py` writes the hash into every run manifest.
- Add a SYNTHETIC daily OHLCV sample, generated by a committed seeded script, so CI can run. Choosing a real
  redistributable sample is left to the owner.
- Add `DATA_SOURCES.md`, which records each source's terms and what CI uses.

## Impact

- Affected specs: new capability `market-data`.
- Affected code: `python/openquant/data.py`, `python/openquant/_sample_data/`,
  `scripts/data/make_synthetic_sample.py` and `experiments/run_pipeline.py`. Also the data docs page and
  `DATA_SOURCES.md`.
- No new dependencies. Polars (already required) reads and writes the Parquet.
- No change to existing `openquant.data` functions or results.
